# 网页检索执行前约束

2026-11-01，用户明确要求执行前硬拦截，不能只依赖模型指令；保留本地计算、文件处理与开发能力。

`contract-impact = semantic`。复用固定 Runtime 的工具分发入口、turn-scoped ExtensionData、FunctionCallError::RespondToModel 和现有工具生命周期；不新增公共 RPC、字段、审批授权或沙箱权限，不启用用户/项目/plugin hooks。直接在 tool.handle 前检查，拒绝时原工具不执行。固定上游源码不修改，新增可重放补丁，在 canonical 构建工作区构建；复用原 Cargo 缓存。部署消费者为 Host 与 Desktop，按本次用户授权的固定开发入口正常退出后增量重启。保留 r5 来源及产物；新 Runtime 来源、同形 schema 和消费者 pin 必须验证后才激活。

设计约束：

- 本轮观察到供应商内置 web_search 或 Kimi Search/Pro/Fetch 调用后，阻止命令中的网页抓取操作。识别 shell 网络下载命令、Python/Node 网络读取，以及由这些解释器执行的本地脚本；纯计算、打印代码/URL、文件处理、localhost 开发请求保留。
- 命令和检索工具的失败按工具、规范化参数、实际工作目录和权限记录。响应输出的明确网络错误也按失败处理，不仅依赖退出码。相同操作仍在运行时要求等待原调用，不启动重复进程。
- 再次执行前比较相关参数、权限与工作目录文件快照；变化后允许重试。轮结束自动释放状态，新用户轮不继承自动重试限制。记录有界、仅进程内，不修改历史库或持久化原始命令/输出。
- 原命令允许执行、正常工具输出/异常失败都沿原链路；拦截原因使用固定中文消息与固定代码返回给模型，不能伪造成功、退出码或实际执行事件。
- 安全验证仅用普通命令与合成协议记录，不强杀、不替换可执行文件、不破坏权限、不实施攻击注入。

通用外部 Hook 不适合直接承担此要求：当前固定版本的 Bash hook 只投影 command，丢失实际 workdir；失败工具不一定运行 PostToolUse；hook 执行异常默认不阻止命令。这里复用工具分发机制以避免这些缺口。

边界与兼容：

- 这是对常见命令、解释器脚本和本轮已跟踪交互式输入的确定性执行策略，不是任意动态程序的网络沙箱，也不能干预供应商内部未暴露的搜索重试。
- 有限文件观察不完整时不声称“条件未变”；权限、输入、相关配置发生变化，或观察到成功安装依赖/修复配置后，允许重新执行。网络失败不因无关输出文件变化而解除限制。
- 已成功的搜索内容中提及错误名不会被当作工具失败；打印代码示例、普通文件传输、开发环境 localhost 请求、包管理和明确 API 写入保留原行为。
- 原生拦截 Warning 由 Host 映射为已有诊断通道的固定代码，Desktop 以固定中文原因展示，不直接透传原始错误、命令或路径。拦截不生成虚假的“运行了命令”记录。

本地验证入口：`scripts/build-web-retrieval-guard.sh` 执行 8 项定向单测、核心 Clippy 和 canonical release 编译，并验证完整 r5 补丁链及 269 份 app-server schema 摘要不变。Host 的 `TestYijieRetrievalExecutionGuardRuntime` 使用该真实产物、回环模型协议和普通命令验证执行前拒绝、可见原因及正常操作；最终验证/激活记录由 Host 的 `docs/web-retrieval-routing.md` 登记。测试不调用真实供应商。
